# GGUF inspection

`nuclis inspect` reads a GGUF file's directory without loading weights for
execution: it validates the container, the metadata, and every tensor's span
and encoding, for any architecture. It does not check a model's equations,
decode quantized values, or tokenize; the adapters bind the tensors
([models/qwen3.8.md § Structural validation](../models/qwen3.8.md#structural-validation))
and the backends run them.

## Run it

Use Zig 0.17.1 from the repository root:

```sh
zig build -Doptimize=ReleaseSafe
./zig-out/bin/nuclis --help
./zig-out/bin/nuclis inspect
./zig-out/bin/nuclis inspect --model /path/to/model.gguf --json
zig build test
```

Without `--model`, inspection reads the configured `engine.model` under
`~/.nuclis/models/`; an absolute `NUCLIS_HOME` overrides the root. `--model` takes precedence
and works without a home directory; relative explicit model paths use the
working directory. Inspection and help never create directories or settings.

JSON has `schema_version: 2`; architecture support is reported by `validate`, not by inspection. Text and JSON
derive from the same snapshot. Declared dimensions are metadata, not verified
runtime capabilities. Failures return a nonzero exit status and an error name on
stderr. Unsupported layouts fail explicitly rather than producing guessed sizes.
Inspection does not compute a checksum; use the command in the
[model specification](../spec.md#4-supported-models-and-artifacts) to check identity.

## Code and ownership walkthrough

1. [main.zig](../../src/main.zig) receives `std.process.Init`, parses
   arguments, and passes the allocator, Io, environment, and buffered stdout to
   the CLI. It flushes output and turns returned errors into an exit status.
2. [paths.zig](../../src/paths.zig) resolves the model path from supplied
   strings. It performs no I/O and returns caller-owned memory.
3. [gguf.zig](../../inference/src/formats/gguf.zig) separates `open`, the file
   I/O shell, from `parse`, which accepts a reader and complete file size. Tests
   use `std.Io.Reader.fixed` over small generated byte arrays.
4. Parsing returns an owning `Document`. Its arena holds names, scalar metadata,
   tensor descriptors, and validation scratch storage. `errdefer` frees partial
   results; `deinit` releases successful results. Returned slices borrow the
   document, so do not deinitialize it while those slices are in use or free two
   copies of the same owning value.
5. Metadata arrays retain their type, count, and file offset. Numeric arrays of
   at most 64 items (`retained_array_items`) also retain their values, allowing
   adapters to validate small configuration arrays such as RoPE sections and
   per-layer patterns. The parser walks larger arrays without materializing the
   vocabulary; `ArrayReader` reads them later from a borrowed directory image.
6. [encoding.zig](../../inference/src/tensor/encoding.zig) sizes stored blocks
   independently of architecture. Dimension zero is the contiguous row: each row
   must hold complete quantization blocks. Checked arithmetic rejects overflow.
7. [inspect.zig](../../src/inspect.zig) builds one snapshot borrowing the
   document and caller-provided histogram storage, then renders it before either
   expires. Model-controlled strings are escaped for safe terminal output.

The parser checks duplicate names, ranks, nonzero dimensions, supported layouts,
alignment, file bounds, and overlapping tensor spans. It sorts a copy of tensor
descriptors for overlap checks while preserving the original directory order.
It consumes the directory, not tensor values; the buffered file reader may read
ahead slightly into the payload. It does not scan or map the complete weight file.

Default limits are 64 MiB of directory bytes, 16,384 metadata entries, 100,000
tensors, 1 MiB per string, and 4,000,000 items per metadata array. Nested arrays,
big-endian containers, other GGUF versions, and unknown layouts are explicitly
unsupported. File-size validation assumes the file remains
unchanged during inspection. No model compatibility or peak-memory estimate is
implied by successful parsing.

The storage table follows the primary
[GGUF format](https://github.com/ggml-org/ggml/blob/master/docs/gguf.md) and
[GGML block definitions](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-common.h).
These references specify layouts; no external implementation was copied.
Value decoding and its fixtures are in [quantization.md](quantization.md).

## Validation

Root tests cover malformed and truncated input, duplicate entries, arithmetic
overflow, alignment, overlaps, allocation failure cleanup, CLI arguments, path
resolution, and JSON/text rendering. They use `std.testing.allocator` and require
no network, GPU, or model download. Both packages also pass their independent
test targets.

Debug and ReleaseSafe builds were exercised on the actual model. Additional
process checks covered JSON inventory, `NUCLIS_HOME` through a temporary model
symlink, help without directory creation, and a truncated file returning a clean
error. These establish inspection behavior only; numerical accuracy is held by
the [CPU reference](cpu-reference.md) and the [Metal backend](metal-backend.md)'s checks.
